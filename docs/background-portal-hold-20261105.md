# 포털 요청 제한 후 백그라운드 검색 대기

실제 반려동물 의료비 검색에서 정보공개포털 응답 429가 발생했다. 앞단 검색은 반복 호출을 멈추지만 백그라운드 작업이 즉시 같은 포털에 접속할 수 있는 빈틈을 확인했다.

이제 앞단의 요청 제한 상태를 검색 실행기에 전달한다. 실행기는 실패·미조회 쪽을 보관하고 5분 동안 대기한 뒤 자동으로 이어서 시도한다. 대기 중 실행 자리는 반환하며 기존 검색량 제한을 계속 적용한다. 5분은 앱의 보수적인 대기값으로, 포털의 제한 해제 시각을 의미하지 않는다. 여전히 제한되면 기존 실패 재시도 정책이 적용된다.

실제 포털에서 확인된 사실은 수정 전 429 발생까지다. 자동 시험에서 제한 상태 전달, 대기 중 페이지 요청 중단, 대기 시간이 지난 후 보관된 쪽부터 재개를 확인했다. 수정본의 실제 운영 재개는 아직 검증하지 않았다. 배포 시 실행기를 먼저 갱신해야 앞단의 대기 요청이 적용된다.

백그라운드 검색 도중 제한이 발생해도 같은 대기 정책을 적용한다. HTTP 상태 429와 HTTP 성공 응답 안의 `code: 429`를 모두 제한으로 인식한다. 실제 포털에서 관측한 것은 후자의 응답 코드다. 두 형태와 대기 후 같은 쪽 재개는 자동 시험으로 확인했다.
